# Containerization and Orchestration: How It Works Under the Hood

> 🌐 **Language:** English (branch `main`) · [Русская версия → branch `main-rus`](https://github.com/KeladKaal/containerization-and-orchestration/tree/main-rus)

An in-depth course for engineers who already run Docker and Kubernetes every day.

This course is not about *how to use* containers — you already do. It's about **how they work underneath**: which Linux kernel mechanisms, which components and protocols sit behind the familiar commands, where the abstractions leak, and why. We take something familiar — `docker run`, an image, a Pod, a Service — and go one layer down.

Assumes you're comfortable with containers and Kubernetes in daily work. Prior knowledge of Linux internals is helpful but not required.

## Lectures

Eight lectures, 1.5 hours each. Every lecture has three logical blocks (~25–30 min). Click a lecture to see its notes.

1. [Docker: containers and images under the hood](lecture-1-docker/) — namespaces, cgroups, capabilities/seccomp, images and layers, overlayfs, the `dockerd → containerd → runc` stack, building and shipping
2. [Observability and monitoring](lecture-2-observability/) — metrics, logs, traces; Prometheus, Grafana, Alertmanager, golden signals, alerts
3. [Kubernetes control plane](lecture-3-kubernetes-control-plane/) — the declarative model and reconciliation, API server, etcd, scheduler, extending the API (CRDs, operators, admission)
4. [Scheduling and resources](lecture-4-scheduling-resources/) — the scheduler from the inside, requests/limits and QoS, OOM/eviction, storage and StatefulSet
5. [Kubernetes networking](lecture-5-kubernetes-networking/) — CNI, Services and load balancing, kube-proxy, DNS, network policies, eBPF / Cilium
6. [Service mesh and advanced traffic](lecture-6-service-mesh/) — data plane vs control plane, Envoy, mTLS, traffic management, ambient / eBPF
7. [MLOps](lecture-7-mlops/) — invited lecture
8. [AI infrastructure](lecture-8-ai/) — bonus lecture

## Running example

The whole course follows one small online shop, `shop`, made of three services:

- `api` — a stateless HTTP service, several replicas;
- `worker` — a background order processor;
- `postgres` — holds the state.

Each lecture drops one layer deeper into this same example — from a process in a container to networking, mesh, and observability.

## Labs

Right now the repository publishes the labs for lectures 1 (Docker) and 2 (monitoring) — a [`lab.md`](lecture-1-docker/lab.md) inside the lecture folder. The Kubernetes labs (lectures 3–6) are not published yet. Each lab is **one engineering mission with a verifiable outcome** (build a container by hand, set up monitoring for a service, and so on), not a set of disconnected steps.

Everything is designed to run **locally and for free** (kind / k3d / minikube) — no cloud access required. The services under test are simple and **generated by AI from a concrete spec** — programming is not the goal of the course; the learning is the devops work around the service. **Mandatory in every lab — monitoring.** The stack (Prometheus + Grafana + Alertmanager, logs and traces) is set up in lab 2 and reused afterward: in every lab you decide which metrics to put on a dashboard and pick **3 metrics to alert on**, with a rationale.

## Using AI in this repo

Using an AI assistant is allowed and encouraged — but this repo is set up so it **helps you learn instead of handing you finished answers**: it works step by step, explains the reasoning, and checks your understanding before moving on.

The rules live in [`AGENTS.md`](AGENTS.md) (and `CLAUDE.md` for Claude Code). Most AI tools pick these up automatically. **If yours doesn't, just point it at [`AGENTS.md`](AGENTS.md)** and ask it to follow the file.
